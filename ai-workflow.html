A Complete Guide to Vibe Coding

Build Anything with AI as Your Thought Partner

You don't need to know how to code. You need to know how to think clearly and describe what you want. AI has changed everything—and this guide will show you exactly how to harness it.

🔍 Full Transparency

This entire website was built using AI. Every line of code, every design decision—created through conversation with AI assistants, guided by NARBE House volunteers. We have no professional developers on staff. We have intent, patience, and the willingness to iterate.

Here's the thing: you don't even need this website. If you learn to ask the right questions, AI can teach you everything here and more. But we've compiled this guide to give you a head start—a roadmap that took us months of trial and error to discover.

01

Why AI Changes Everything

For decades, building software required years of study. Now, the barrier isn't knowledge—it's clarity of thought.

The Old Way vs. The New Way

In the past, if you wanted to build a simple app—say, a button that plays a sound when pressed—you needed to:

  • Learn HTML (the structure of web pages)
  • Learn CSS (how things look)
  • Learn JavaScript (how things behave)
  • Understand browser APIs (how to actually play audio)
  • Debug cryptic error messages
  • Spend weeks or months getting something basic working

Now? You describe what you want to an AI, and it writes the code. When it doesn't work, you show the AI the error, and it fixes it. The skill has shifted from "knowing programming languages" to "knowing how to describe what you want clearly."

💡 The Core Insight

Programming is really just problem decomposition—breaking a big problem into smaller pieces and solving each piece. AI is extraordinarily good at the "solving each piece" part. Your job is the decomposition: figuring out what pieces you need.

What Is "Code" Anyway?

Before we go further, let's demystify what code actually is. Code is just text that computers can read and follow. It's like a recipe—step-by-step instructions written in a language computers understand.

For web-based tools (which is what we'll build), there are three types of code:

  • HTML — The structure. "Put a button here, a title there." Like the bones of a body.
  • CSS — The appearance. "Make the button blue and big." Like the clothes and makeup.
  • JavaScript — The behavior. "When clicked, play a sound." Like the brain and muscles.

You don't need to learn these languages. AI will write them for you. But understanding what they do helps you communicate with AI better. If something looks wrong, you can say "the CSS seems off" instead of "it's broken somehow."

📄 What's a "File"?

Code lives in files, just like documents. A file named index.html contains HTML code. The .html ending (called an "extension") tells the computer what type of file it is.

For simple projects, you can put ALL three types of code (HTML, CSS, JavaScript) in a single .html file. That's what we'll do in the next section—one file that does everything.

Why Start with HTML? (Other Languages Exist!)

HTML/CSS/JavaScript are just one family of programming languages. There are many others, each designed for different purposes:

  • Python — Great for desktop apps, automating tasks on your computer, data analysis, and AI. If you want to make something that runs directly on Windows/Mac (not in a browser), Python is often the choice.
  • Swift — Apple's language for iPhone and iPad apps.
  • Kotlin / Java — For Android phone apps.
  • C# (C-Sharp) — For Windows desktop apps and games (Unity).
  • SQL — For working with databases (storing and retrieving information).

So why do we start with HTML?

  • Zero setup — Just save a file and open it in your browser. No installation needed.
  • Instant feedback — Make a change, refresh the page, see the result immediately.
  • Works everywhere — Phones, tablets, computers—any device with a browser.
  • Easiest to debug — Visual problems are obvious; you can see what's wrong.
  • AI is great at it — Web code is extremely well-documented online, so AI models are very good at writing it.

🐍 Want to Try Python Later?

Once you're comfortable with HTML and the Vibe Coding workflow, Python is a natural next step. At NARBE House, we use Python for things like:

• Automating repetitive tasks on a computer
• Converting file formats in bulk
• Processing data (like organizing large lists)
• Building tools that don't need a visual interface

The process is the same: describe what you want to AI, get code, run it, iterate. The only difference is you run Python files differently than HTML files. AI can teach you when you're ready!

What "Vibe Coding" Actually Means

The term "Vibe Coding" comes from the idea that you're communicating the essence of what you want—the vibe—rather than the technical implementation. You say "I want it to feel calm and accessible" instead of "use a 16px font with #333 color and 1.6 line-height."

But here's the crucial part that many people miss: Vibe Coding is not magic. It requires:

  • Clear thinking — You must understand your own problem deeply
  • Patience — The first output is rarely perfect; iteration is normal
  • Verification — AI can be wrong; you must test and validate
  • Persistence — Complex projects take many conversations, not one

Your First Build: 15 Minutes to "I Made This"

Stop reading, start doing. In the next 15 minutes, you'll build a working app—a button that plays a sound. This is the fastest way to understand what Vibe Coding feels like.

⚡ What You Need

• A computer (Windows, Mac, or Chromebook)
• A web browser (Chrome, Firefox, Edge, Safari—any works)
• 15 minutes of focus

That's it. No downloads. No accounts (yet). No credit card.

Step 1: Open an AI Chatbot

Go to one of these AI chat services. They're all free to start:

🤖
ChatGPT
Most popular, easy to use
🧠
Claude
Great for detailed explanations
✨
Google Gemini
No signup if you have Google account

Create an account if needed (takes 1-2 minutes). Once you see a chat box, you're ready.

Step 2: Ask AI to Build Your App

Copy and paste this exact prompt into the chat:

Copy This Prompt
I'm brand new to coding and want to build my first app. Please create a single HTML file that shows one big button on the screen. When I click the button, it should play a pleasant chime sound. Requirements: - The button should be LARGE (taking up most of the screen) - High contrast colors (dark background, bright button) - The text should say "PRESS ME" - Include the sound directly in the code (use a base64 encoded sound or generate a tone with JavaScript) - Add a simple instruction at the top that says "Tap the button to hear a sound" Please give me the complete code I can save as a file. After the code, briefly explain how I would add my own sound file later.

Press Enter and wait. AI will give you a block of code—it'll look like a wall of strange text. That's perfect.

Step 3: Save It as a File

This is the part many guides skip. Here's exactly how to save code as a file:

On Windows:

  1. Copy the code — Click the copy button AI shows (usually in the corner of the code block), or select all the code and press Ctrl+C
  2. Open Notepad — Press the Windows key, type "Notepad", press Enter
  3. Paste the code — Press Ctrl+V (you should see all that code appear)
  4. Save with the right name — Press Ctrl+Shift+S (Save As), then:
    • Navigate to your Desktop (so you can find it easily)
    • In "File name", type: my-first-app.html
    • In "Save as type", select: All Files (*.*)
    • Click Save

On Mac:

  1. Copy the code — Click copy or select all and press Cmd+C
  2. Open TextEdit — Press Cmd+Space, type "TextEdit", press Enter
  3. Switch to plain text — Go to Format menu → Make Plain Text (important!)
  4. Paste the code — Press Cmd+V
  5. Save with the right name — Press Cmd+Shift+S, then:
    • Navigate to Desktop
    • Name it: my-first-app.html
    • Uncheck "If no extension is provided, use .txt"
    • Click Save

⚠️ The Extension Matters!

The file MUST end in .html — not .txt or .html.txt. If Windows or Mac adds .txt automatically, your browser won't recognize it as a web page.

If you see my-first-app.html.txt on your desktop, rename it to remove the .txt part.

Step 4: Open It in Your Browser

Find the file on your Desktop. It should have an icon that looks like your web browser (Chrome, Firefox, etc.). Double-click it.

Your browser will open, and you should see your button. Click it!

🎉 Did It Work?

If you heard a sound: Congratulations! You just built your first app with AI. You're officially Vibe Coding.

If something went wrong: That's completely normal. Go to Step 5.

Step 5: Fix Any Problems (The Real Skill)

If it didn't work, this is actually the most valuable part of Vibe Coding: learning to fix things with AI's help.

Common Issues and What to Tell AI:

If Nothing Appears
"I saved the code and opened it in my browser, but I just see a blank page. Here's what I did: [describe your steps]. What might be wrong?"
If the Button Appears but No Sound
"The button shows up but when I click it, no sound plays. I'm using [Chrome/Safari/Firefox] on [Windows/Mac]. Is there something I need to do to enable sound?"
If You See the Code Instead of a Button
"When I open the file, I see all the code text instead of a button. I think the file didn't save correctly. Can you help me figure out what went wrong?"

The key skill: Describe exactly what you see and what you expected. AI can almost always figure out what went wrong.

Step 6: Make It Yours

Now that it works, try asking AI to modify it. Here are some ideas:

  • "Can you change the button color to green?"
  • "Can you make the button even bigger?"
  • "Can you add a second button that plays a different sound?"
  • "Can you make the button say 'Hello!' instead of playing a sound?"

Each time AI gives you new code, save it (overwrite the old file or create a new one) and refresh your browser to see the changes.

🎯 What You Just Learned

You didn't just build a button. You learned the core loop of Vibe Coding:

1. Describe what you want to AI
2. Save the code AI gives you
3. Test it in your browser
4. Iterate by telling AI what to fix or change

That's it. Everything else in this guide—tools, techniques, best practices—builds on this simple loop. Now let's understand it more deeply.

03

AI as a Thought Partner (Not Just a Code Generator)

The biggest mistake beginners make is treating AI like a vending machine. Put in request, get code out. That's not how this works.

The Right Mental Model

Think of AI as a highly skilled collaborator who:

  • Has broad knowledge but doesn't know your specific situation
  • Can suggest approaches but needs your feedback to refine them
  • Works best with conversation, not one-shot requests
  • Can explain its reasoning if you ask
  • Will confidently give wrong answers sometimes (more on this later)

⚠️ Critical Understanding

AI doesn't "understand" in the way humans do. It predicts what text should come next based on patterns. This means it can produce plausible-sounding nonsense. Always verify important information.

How to Have Productive Conversations

Start with Context, Not Requests

Before asking for code, explain your situation. The more context you provide, the better the AI can help.

Example: Good Context-Setting
"I'm a caregiver for my 14-year-old son who has cerebral palsy. He can use a single head-switch to interact with devices. I want to build a simple web app that plays his favorite song when he activates the switch. He loves immediate audio feedback. I have no programming experience but I'm comfortable using a computer. Can you help me understand what I need to do?"

Notice how this prompt doesn't immediately ask for code. It establishes:

  • Who you are (caregiver, no programming experience)
  • Who you're building for (14-year-old with cerebral palsy)
  • The constraints (single head-switch)
  • The goal (play a song on switch activation)
  • The user's preferences (loves immediate feedback)

Ask Questions Before Building

Use AI to explore the problem space before jumping to solutions:

Example: Exploratory Questions
"Before we build anything, can you help me understand: What are the different ways a head-switch could be connected to a computer? What are the trade-offs between them? Are there accessibility standards I should know about?"

Iterate, Don't Start Over

When something isn't right, describe what's wrong rather than starting a new conversation:

Example: Iterative Refinement
"The button works, but it's too small for my son to see easily. Can you make it much larger—maybe taking up most of the screen? Also, he responds better to bright colors. Can we make it bright yellow with a thick black border?"

A Real Conversation Example

Here's what a productive back-and-forth actually looks like:

Notice what happened: The AI asked clarifying questions, confirmed understanding, and offered choices about how to proceed. This is the kind of collaboration that produces good results.

Learning by Watching and Asking

Here's something important: you don't need to understand the code to start building. At first, you'll be "blindly" asking AI to do things, and that's okay. But over time, something magical happens—you start to learn.

Every time AI writes code for you, you can ask it to explain:

Example: Learning Through Explanation
"That code works, but I don't understand it. Can you explain what the 'addEventListener' part does? Why do we need it?"

The AI becomes your teacher. You'll find yourself picking up concepts naturally:

  • "Oh, so functions are like reusable recipes for doing things"
  • "I see—CSS is what controls colors and sizes"
  • "So variables are just named containers for information"

This gradual understanding gives you an edge. When something breaks, you'll start to have intuitions about what might be wrong. When you want a specific change, you'll know how to describe it more precisely. You don't have to become a programmer—but you'll become better at directing one.

🎓 You're Already Learning

Even if you never write a line of code yourself, watching AI work teaches you the logic of programming. You'll understand how pieces fit together, why certain approaches work better, and how to communicate technical ideas.

Ask questions constantly. "Why did you do it that way?" "What would happen if we changed this?" "Can you explain that like I'm five?" There's no such thing as a dumb question—AI has infinite patience.

05

Understanding How AI Works

You don't need to understand AI deeply, but knowing a few concepts will help you use it more effectively and avoid frustration.

What's Actually Inside Your Code?

Now that you've built something, let's briefly understand what AI created for you. If you open your HTML file in a text editor, you'll see something like this: 

<!-- This is HTML - the structure -->
<button id="myButton">Press Me</button>

<!-- This is CSS - the appearance -->
<style>
  button { 
    background: blue; 
    font-size: 24px; 
  }
</style>

<!-- This is JavaScript - the behavior -->
<script>
  document.getElementById('myButton').onclick = function() {
    // play sound code here
  }
</script>

You don't need to understand this code. But knowing that <style> controls appearance and <script> controls behavior helps you say things like: "The button looks wrong—can you fix the style part?" or "The click isn't working—check the script section."

What Are Tokens?

When you chat with AI, your messages are broken down into small chunks called tokens. A token is roughly 3-4 characters or about ¾ of a word. For example:

  • "Hello" = 1 token
  • "Hello, how are you?" = 5 tokens
  • A typical paragraph = 50-100 tokens
  • A full page of code = 300-500 tokens

Both your messages AND the AI's responses use tokens. A long conversation with lots of code can quickly add up to thousands of tokens.

What's a Context Window?

The context window is how much the AI can "see" at once—your entire conversation plus any code or files you've shared. Think of it like the AI's working memory.

  • Small context window (8K tokens) — Can see about 6,000 words or a few pages of code
  • Medium context window (32K tokens) — Can see about 25,000 words or a small project
  • Large context window (128K+ tokens) — Can see about 100,000 words or an entire codebase

💡 Why Context Windows Matter

When your conversation gets too long, older messages "fall off" the context window—the AI literally forgets them. This is why AI might suddenly forget something you told it earlier, or ask you to repeat something.

In code editors like VS Code with Copilot, the AI can often see your open files automatically. This is incredibly powerful—it understands your project structure without you having to explain everything.

Practical Impact

Context windows affect how you work:

  • Long conversations use more tokens — Starting fresh can be more efficient than continuing a very long chat
  • Code editors have an advantage — They feed relevant code to the AI automatically, using context wisely
  • Bigger isn't always better — Larger context windows cost more; use what you need
  • Be strategic — If AI forgets something important, paste it again or start a new conversation focused on that topic

Why Some Models Cost More

Not all AI models are equal. More powerful models can:

  • Handle longer conversations without forgetting context
  • Write more accurate, complex code
  • Better understand nuanced requests
  • Make fewer mistakes

This extra capability requires more computing power, which costs more money. Think of it like cars: a basic sedan gets you where you need to go, but a high-performance vehicle offers more speed and features at a higher price.

How Pricing Works

AI services typically offer two pricing models:

1. Subscription Plans (Monthly Fee)

Pay a flat monthly fee (usually $10-20/month) and get a set amount of usage included. This is what most people start with because it's predictable.

  • ChatGPT Plus: $20/month — includes generous usage of GPT-4o
  • Claude Pro: $20/month — includes usage of Claude Sonnet
  • GitHub Copilot: $10-19/month — integrated into your code editor

Important: Even with subscriptions, there are usually rate limits—caps on how many messages you can send per hour or per day. If you hit the limit, you'll need to wait or switch to a different model temporarily.

2. Pay-As-You-Go (API Usage)

Pay only for what you use, measured in tokens. This is more advanced and typically used by developers building apps, but some services offer it directly.

  • You're charged per 1,000 tokens (input and output separately)
  • You can usually set spending limits to avoid surprises
  • Good for occasional use or when you need the most powerful models

⚠️ Running Out of Tokens

This will happen. You'll be in the middle of a coding session and suddenly hit a limit. When this happens, you have options:

• Wait — Limits usually reset hourly or daily
• Switch models — Use a less powerful (but still capable) model temporarily
• Start a new conversation — Long conversations use more tokens; starting fresh can help
• Use the free tier — Most services have a free tier you can fall back to

Tips for Managing Usage

  • Be concise — Shorter prompts use fewer tokens
  • Don't repeat yourself — AI remembers the conversation; no need to re-explain
  • Start fresh when changing topics — Old context uses tokens even when irrelevant
  • Use the right model for the task — Simple questions don't need the most powerful model
  • Set spending alerts — If using pay-as-you-go, set up budget notifications

🎯 Practical Advice

Start with a $20/month subscription to ChatGPT Plus or Claude Pro. This gives you plenty of usage for learning and building simple projects. You'll rarely hit limits unless you're doing heavy, all-day coding sessions.

If you do hit limits frequently, that's actually a good sign—you're building a lot! At that point, consider GitHub Copilot for code-specific work, or explore pay-as-you-go options.

How to Verify AI Information

AI can be confidently wrong. This is perhaps the most important skill to develop: knowing when and how to verify what AI tells you.

When AI Gets Things Wrong

AI models are trained on vast amounts of text from the internet. This means they can:

  • Hallucinate — Make up facts, URLs, or documentation that doesn't exist
  • Be outdated — Their knowledge has a cutoff date; newer information isn't included
  • Mix up details — Confuse similar concepts or combine information incorrectly
  • Be confidently wrong — State incorrect things with the same tone as correct things

🧠 Key Principle

AI is a brilliant assistant with no concept of truth. It generates plausible text based on patterns. Something sounding confident doesn't make it correct. Always verify anything important.

Verification Strategies

1. Test Code Immediately

For code, the best verification is simple: run it and see if it works. Don't take AI's word that the code is correct—put it in a file, open it in a browser, and test every feature.

2. Ask for Sources

When AI gives you factual information, ask: "Can you provide official documentation or sources for this?" Then actually visit those links. AI sometimes makes up URLs that look real but lead nowhere.

3. Cross-Reference

For important decisions, ask multiple AI tools the same question and see if they agree. Or do a quick web search to verify. If something seems unusual, it probably deserves a second look.

4. Ask "Are You Sure?"

Surprisingly effective: simply ask "Are you certain about that? Please double-check." AI will sometimes catch its own mistakes when prompted to review.

5. Understand the Limits

AI is most reliable for:

  • Common programming patterns and syntax
  • Well-documented technologies
  • General explanations and concepts

AI is less reliable for:

  • Recent events or new software versions
  • Specific numbers, dates, or statistics
  • URLs, citations, or references
  • Niche or obscure topics

The Error-Fix Loop

When code doesn't work, you'll see errors. Here's how to handle them:

  1. Open Developer Tools In your browser, press F12 (or right-click anywhere on your page and select "Inspect"). A panel will open—it might be at the bottom or side of your screen.
  2. Click the "Console" Tab You'll see tabs like "Elements", "Console", "Network". Click "Console". This is where errors appear in red text.
  3. Copy the Exact Error Don't paraphrase. Don't interpret. Copy the exact red text, including any line numbers.
  4. Paste to AI with Context Say something like: "I'm getting this error when I click the button: [paste error]. Here's my code: [paste relevant code]. What's wrong?"
  5. Apply the Fix and Test Again Make the changes AI suggests. Refresh the page. Test. If there's a new error, repeat the process.
Example: Error Reporting
"I clicked the Play Sound button but nothing happened. The console shows this error:

Uncaught TypeError: Cannot read properties of null (reading 'play') at playSound (app.js:15:23)

Here's my playSound function: [paste code]. What's wrong?"

🔧 What Developer Tools Looks Like

Don't be intimidated when you open it—it's made for professionals and has lots of confusing options. You only need the Console tab.

• Red text = Errors (something broke)
• Yellow text = Warnings (something might be wrong, but it still works)
• White/gray text = Regular information (usually fine to ignore)

The most useful part: error messages often include a line number (like "at line 15"). That tells you exactly where in your code the problem is. Share this with AI!

07

The Complete Workflow

Here's the full process from idea to working application. This is what we use at NARBE House for every project.

Phase 1: Discovery (Before Any Code)

  1. Define the User Who exactly is this for? What are their abilities? What devices do they use? What's their environment like? Write this down. You'll share it with AI.
  2. Define the Core Need What is the ONE main thing this needs to do? Don't say "a communication app"—say "a way to request 'bathroom' with one button press that speaks out loud."
  3. List the Constraints What are the limitations? Single switch? No internet? Must work on iPad? Needs to be extremely simple? Constraints are helpful—they focus the solution.
  4. Explore with AI Before asking for code, have a conversation. Ask what approaches exist. Ask about trade-offs. Ask what you might not be thinking about. Let AI help you understand the problem space.

Phase 2: Building (The Iterative Loop)

  1. Start Small Ask AI to build the simplest possible version. One button, one action. Get that working before adding complexity.
  2. Test Immediately Save the file. Open it in a browser. Does it work? Test every feature as it's added. Don't write 500 lines before testing.
  3. Fix Errors as They Appear Error → Copy → Paste to AI → Apply fix → Test again. This loop is normal. Even experienced developers do this constantly.
  4. Add Features One at a Time Get the button working. Then add the sound. Then add the visual feedback. One feature, test, confirm, next feature.
  5. Save Checkpoints When something works, save a copy (or use Git to commit). This way, if you break something later, you can go back to the working version. 
# If you want to learn Git (optional but valuable):

git init                              # Start tracking this project
git add .                             # Stage all files
git commit -m "Button plays sound"    # Save checkpoint with description

# Later, if you break something:
git log --oneline                     # See your checkpoints
git checkout [commit-id]              # Go back to a working version

Phase 3: Refinement (Polish & Handoff)

  1. Test with the Actual User Put it in front of the person it's for. Watch them use it. What's confusing? What's frustrating? What delights them?
  2. Iterate Based on Feedback "The button is too small" → Ask AI to make it bigger. "The sound is too quiet" → Ask AI to add volume control. Real user feedback drives real improvements.
  3. Document What You Built Create a README file that explains: what this is, who it's for, how to use it, and any known issues. Future you will thank present you.
  4. Share It If it helps one person, it might help others. Consider sharing with the accessibility community. Open source your code. Pay it forward.

The README: Your Project's Memory

A README file is a text document (usually named README.md) that lives in your project folder. It serves multiple purposes:

  • For you: Reminds you what you built and why, especially months later
  • For AI: Give it to the AI at the start of each session to restore context
  • For others: Helps anyone else understand and use your project
# Example README.md structure:

# Ben's Soundboard

A simple sound-playing app for my son Ben (14, cerebral palsy, single-switch user).

## What It Does
- Large buttons in a 2x3 grid
- Each button plays a different sound
- Works with keyboard (spacebar scans through options)

## How to Use
1. Open index.html in a browser
2. Tap any button to hear the sound
3. Press spacebar to scan (auto-highlight moves every 2 seconds)

## Known Issues
- Sound doesn't work on iOS until user taps once (browser limitation)

## Future Ideas
- Add volume control
- Let Ben record his own sounds

Git & GitHub: Your Safety Net

Git and GitHub might sound intimidating, but they're incredibly useful tools that save you from disaster and make collaboration possible. Here's what you need to know.

🤖 Good News: AI Handles Most of This For You

You don't need to memorize Git commands. When you use VS Code with Copilot or Cursor, the AI assistant can:

• Run Git commands for you when you ask
• Write commit messages automatically based on your changes
• Explain what's happening when something goes wrong
• Guide you through publishing to GitHub step by step

This section explains what these tools are so you understand what's happening behind the scenes. But in practice, you'll mostly just click buttons and let AI handle the details.

Git vs. GitHub: What's the Difference?

These two things are related but different:

  • Git is a tool that runs on your computer. It tracks every change you make to your files, like an infinite undo button. It's free and works offline.
  • GitHub is a website where you can store your Git projects online. Think of it like cloud storage specifically designed for code projects.

You can use Git without GitHub (just local backups), but GitHub adds the ability to:

  • Access your code from any computer
  • Share projects with others
  • Collaborate with other people on the same project
  • Show off your work (like a portfolio)
  • Get free web hosting for simple sites (GitHub Pages)

Why This Matters for Vibe Coding

When you're building with AI, things will break. You'll make a change that seemed like a good idea, and suddenly nothing works. Without Git, you're stuck trying to remember what you changed. With Git:

  • Every working version is saved — Go back to any previous state instantly
  • You can experiment fearlessly — Try risky changes knowing you can undo them
  • AI can help you use it — Just ask! "How do I undo my last commit?"

💡 The Video Game Analogy

Git commits are like save points in a video game. You save before a boss fight so if you die, you don't start over from the beginning. In coding, you commit before making big changes. If the change breaks everything, you reload your save.

Getting Started with Git

Git comes built into VS Code, so if you followed the setup guide, you already have it. Here's the simplest workflow:

First Time Setup (Once Per Project)

Open the terminal in VS Code (View → Terminal) and run: 

git init
# This tells Git to start tracking this folder

Saving Your Work (Do This Often)

git add .
# Stage all your changes (the dot means "everything")

git commit -m "Added sound button feature"
# Save a checkpoint with a description

Going Back to a Previous Version

git log --oneline
# See all your save points (press Q to exit)

# You'll see something like:
# a1b2c3d Added sound button feature
# e4f5g6h Initial setup

git checkout e4f5g6h
# Go back to that specific save point

🤖 Let AI Help You With Git

Don't memorize commands! In VS Code with Copilot, just ask in the chat:

• "How do I save my current progress with Git?"
• "I broke something, how do I go back to my last working version?"
• "What's the difference between git add and git commit?"
• "How do I see what files I've changed?"

Copilot understands Git deeply and will give you the exact commands for your situation.

Connecting to GitHub

Once you have a project you want to back up online or share, you can push it to GitHub:

  1. Create a GitHub Account Go to github.com and sign up (free).
  2. Create a New Repository On GitHub, click the "+" button and "New repository". Give it a name (like "my-sound-button"). Keep it public or make it private.
  3. Connect Your Local Project GitHub will show you commands to run. It looks something like: 
    git remote add origin https://github.com/yourusername/my-sound-button.git
git branch -M main
git push -u origin main
  4. Push Changes Going Forward After committing locally, upload to GitHub with: 
    git push

Or let VS Code do it for you: Click the Source Control icon in VS Code (looks like a branch), and it will guide you through publishing to GitHub with buttons instead of commands.

Using AI to Help with Git

One of the best things about AI coding assistants is that they're experts at Git. Here are prompts that work great:

When You're Lost
"I'm in the middle of my project and things are broken. I want to save my current broken state (in case I need it) but then go back to when everything worked. How do I do this with Git?"
When You Want to Experiment
"I want to try adding a new feature but I'm worried I'll break things. Can you help me create a Git branch so I can experiment safely?"
When You Need to Undo
"I just committed something and realized it was a mistake. How do I undo my last commit but keep the files so I can fix them?"
When You're Confused
"Git is showing me a weird message about 'merge conflicts'. I don't know what that means. Can you explain what happened and help me fix it?"

Commit Messages: Leave Notes for Future You

Each commit includes a short description of what changed. This helps when you need to find a specific version later. Here's what good vs. bad messages look like: 

# Good commit messages:
"Add volume slider to sound button"
"Fix: button now works on iOS Safari"
"Change colors to high contrast for Ben"

# Not helpful:
"stuff"
"changes"
"asdfasdf"

🤖 AI Writes These For You

In VS Code, when you go to commit your changes, Copilot can automatically generate a commit message based on what you changed. There's a sparkle button (✨) next to the message box that does this.

The AI reads your changes and writes something like "Add volume slider and update button styles" — usually better than what you'd write yourself! You can edit it or just accept it.

🎯 The Reality: You'll Mostly Click Buttons

VS Code has a visual interface for all of this. Click the Source Control icon (branch symbol) in the sidebar, and you'll see:

• A list of files you've changed
• A text box to write (or auto-generate) your commit message
• Buttons to commit, push, pull, and sync
• Clear visual status of what's staged and what's not

The terminal commands exist and are useful to understand, but most of your Git usage will be clicking buttons in VS Code while AI explains anything confusing. That's the Vibe Coding way.

Troubleshooting Common Problems

Things will go wrong. That's normal. Here are the most common problems beginners face and exactly how to fix them.

File & Saving Problems

Problem: Your file saved as .txt instead of .html.

Fix:

  1. Find the file on your computer
  2. Right-click → Rename
  3. Change my-file.html.txt to just my-file.html
  4. If Windows warns you about changing extensions, click "Yes"

Prevention: When saving in Notepad, change "Save as type" to "All Files" before saving.

Fix: Right-click the file → "Open with" → Choose your browser (Chrome, Firefox, Edge, etc.). You can also check "Always use this app" to make it the default.

Fix:

  • Windows: Check your Documents folder, Downloads, or Desktop. You can also search for *.html in File Explorer.
  • Mac: Check Finder → Recent, or search in Spotlight (Cmd+Space, type the filename).

Prevention: Always save to your Desktop when starting out—it's the easiest place to find things.

Nothing Happens When I Click

Most likely causes:

  • JavaScript error: Press F12, click Console, look for red text. Copy and share with AI.
  • Sound blocked: Browsers block auto-playing sounds. The page may need a "click to enable audio" interaction first. Ask AI to add this.
  • Missing file: If your code references a sound file that doesn't exist, nothing will play.

What to tell AI: "My button shows up but clicking it doesn't do anything. The console shows: [paste any red errors]."

Possible causes:

  • Browser cache: Press Ctrl+Shift+R (Cmd+Shift+R on Mac) to hard refresh
  • You edited and made a typo: Even one missing character can break code. Ask AI to review your recent changes.
  • File moved: If the file references other files (images, sounds), make sure they're all still in the same folder.

It Looks Wrong

What to tell AI:

"The button is showing up too small. I wanted it to take up most of the screen. Here's my current code: [paste code]. Can you fix the CSS to make the button larger?"

Tip: Be specific! Instead of "it looks wrong," say "the button is blue but I wanted green" or "the text is too small to read easily."

Browsers render things slightly differently. If it looks good in Chrome but bad in Safari:

Tell AI: "This looks fine in Chrome but the layout is broken in Safari. Can you add CSS that works in both browsers?"

AI will add "vendor prefixes" or alternative styles to fix cross-browser issues.

AI Gave Me Multiple Files

For more complex projects, AI might split code into multiple files. Here's how to handle that:

  1. Create a project folder — Make a new folder on your Desktop called "my-project"
  2. Save each file inside that folder — Save index.html, styles.css, and script.js all in the same folder
  3. Open index.html — Always open the HTML file; it will automatically load the CSS and JS

Simpler option: Tell AI "Please put everything in a single HTML file" and it will combine them for you.

Code Editor Problems

This is a security feature. If you created the files yourself, click "Yes, I trust the authors" to enable full features.

Check these:

  • Internet connection — AI needs internet to work (except Ollama)
  • Signed in? — Check the bottom-left of VS Code for your account
  • Subscription active? — Free trials expire; check your GitHub/Cursor account
  • Rate limited? — You may have hit usage limits. Wait an hour or upgrade your plan.

🆘 When All Else Fails

Copy your ENTIRE code, go to a fresh AI chat (ChatGPT, Claude, etc.), and say:

"I'm trying to build [describe goal]. Here's my code: [paste everything]. It's not working—[describe the problem]. Can you review the entire thing and tell me what's wrong?"

A fresh AI session with full context often catches things that were missed in a long conversation.
