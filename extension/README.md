# Benny’s Hub Companion — experimental

Load this directory via Chrome/Edge Extensions → Developer mode → Load unpacked. The prepared source directory needs no build step. Maintainers changing the canonical `bennyshub/shared/` scan, voice, badge or backup-validation helpers must run `node scripts/sync-companion-shared.cjs` before reloading; the Companion's copies stay byte-for-byte identical. Prepare this revision with `node scripts/package-companion.cjs --revision=keyboard-wrap` (no Python required), or add `--check` to validate without writing. It keeps manifest version 1.0.8 and packages under `releases/1.0.8-keyboard-wrap/`, preserving the journal-storage candidate, the original 1.0.8 ZIP, 1.0.7 and all earlier candidates unchanged. This is a local candidate, not a submitted or approved store update. It fixes Netflix video framing when provider centering transforms displaced the fitted picture and left only a quarter visible. The fix adds no permissions. This same-version candidate also stores Journal entries/drafts, Keyboard vocabulary/settings, Streaming library/progress/settings and Day Hub weather preferences in Companion local storage, using the existing storage permission. The shared scanner also restores continuous keyboard-row wrapping without changing the default behavior of Companion playback controls. The filename revision identifies the changed candidate; it is not a new Chrome manifest version.

Use the Hub at http://127.0.0.1:4173/bennyshub/index.html during development, or your IDE preview at http://127.0.0.1:3000/bennyshub/index.html. Both ports also support localhost. Reload the Hub after loading or reloading the extension. Open this extension’s settings and turn on **Streaming and news** to grant access to every listed streaming service and the Day Hub news feeds together. The same switch turns that access off; Calendar connects separately. No AI credential or calendar address is bundled.

Streaming opens a dedicated playback window. The candidate reserves an area for the controls and fits the video above it instead of placing the controls over the picture. Its 1.0.8 local candidate follows the Hub's scan interval, input sensitivity, scan mode, parking, Space brake, speech-wait and voice settings, including changes made while a stream is open. Parking, brake and speech-wait preferences are centralized in Hub Settings. Hub Settings uses its ordinary page flow, with no nested scrolling panel. All Scan options remain visible. Scan Speed stays available in both modes because it also controls backward scanning. Parking, Space brake and Wait for speech are disabled until Auto scan is On; loop count also requires Auto park. Disabling an option preserves its saved value. Changing an option retains its highlighted control; input sensitivity stays available in either mode. The four new preferences—Parking, loop count, Space brake and Wait for speech—are not duplicated in Companion or individual app settings. Existing local Auto, scan-speed and voice options remain available. The owner reported 1.0.7 submitted and awaiting review on October 4, 2026; that historical status has not been independently checked in the publisher dashboard. When a provider puts only the video element into native fullscreen, other controls can become inert. The Companion returns to its framed browser window so the dock remains usable with switches and a mouse. Playback keeps the same media element, source and parent; a later Fullscreen selection uses the existing player wrapper where available. This is different from keeping the video element itself in native fullscreen and still needs live provider validation.

- Step mode starts at a blank step with no control highlighted. Space advances, holding Space for three seconds scans backward repeatedly until released, and Enter selects a highlighted control. The blank step appears between loops in either direction; Enter there does nothing.
- Auto scan starts at the blank step and follows the Hub's Parking preference. Off scans continuously through a silent blank step, without announcing Park or Parked. Park when chosen lets Enter at the blank step park scanning. Auto park stops after 1, 2 or 3 complete loops (2 by default). Enter while parked resumes at Play / Pause without activating it. Selecting an ordinary control does not itself force parking.
- Space brake is on by default in Auto scan: pressing Space freezes the current highlight, a short release leaves scanning paused, a second tap resumes, and a hold of at least three seconds resumes on release. Space at the blank step or while parked does nothing. Only a dotted outline marks the selected button while scan-paused, including after scrolling. With speech enabled, Paused is announced after the current label finishes normally; resuming cancels a pending announcement. Actual parking clears the choices and brings the existing Parked status into view. Step mode keeps its existing backward-hold behavior, and its recurring blank step is silent.
- Optional Wait for speech starts a full scan interval after the current label finishes. Failed or unavailable speech falls back to normal timing. Existing input sensitivity remains 50/100/200/300 ms, default 50 ms, with no extra minimum hold.
- Controls stay in one compact ordered row: green for playback, blue for sound, purple for fullscreen and red for Return to Hub, always last. At narrow widths the row scrolls horizontally to keep the highlighted control visible; not every control is on screen at once. Labels remain readable and a yellow outline marks the scan selection. There is no Pause/Resume switches button. For signing in or typing, Alt+Shift+B temporarily releases the keyboard and mouse; press it again to return control to the bar.
- Help includes **Toolbar Speech On/Off**, a Companion-only preference that defaults to On and is saved for this browser profile and updates other Companion windows immediately. On speaks independently of Hub TTS while using the Hub’s selected voice and rate. Off silences automatic labels, parking announcements and control feedback without changing Hub voice settings or video audio. **Say I need help** still speaks when deliberately selected. The mute control keeps the stable label **Mute/Unmute**.
- Return to Hub reuses the launching Hub tab even if its connection is temporarily unavailable. If that tab was closed, it checks for another matching Hub before reopening the verified address in a normal browser window. Repeated return requests share one operation. Closing a player with the window close button does not open another Hub.

Plex startup begins immediately and watches for Play/Resume controls, including links and Resume dialogs. It activates these directly instead of sending simulated X/Enter/P keys. It waits only for the page to supply its controls; an empty video element cannot block the sequence. Browser autoplay rules can still require choosing Play.

After updating the extension, reload it in Chrome/Edge's Extensions page, refresh the Hub, and launch a new stream. Existing player windows can retain the old controls.

## App storage and caregiver backups

Journal entries and drafts are saved automatically in Companion local storage for this browser profile. They are not sent to NARBE LLC, Google Drive or browser account sync. The Hub provides the accessible writing and entry-list interface; Companion keeps the records independently of Hub website storage. The web client checks the `journal-storage-v1` capability rather than the manifest version. With an older Companion it keeps the existing website-storage behavior until the update is installed. On first connection to storage-capable Companion, it merges existing website entries and draft into Companion without discarding the retained legacy copy. Once migrated, Companion is the authoritative store. Normal updates to the same installed extension preserve this storage. Removing Companion or deleting its browser profile removes it.

Keyboard, Streaming and Day Hub use the `app-storage-v1` capability for their app-specific local records. A validated per-app bridge permits only that app’s known keys. Existing Companion values win migration conflicts; conflicting browser-origin values remain in recovery archives included in version 2 exports. With an older Companion, these app records continue using website storage until app-storage support is available; existing tool connection gates remain unchanged. Calendar addresses and streaming-service sign-ins are not part of these app backups.

The existing **Companion & data → My data → Journal → Export Journal** and **Restore journal entries** controls remain the caregiver backup and restore route, now including the draft as well as completed entries. Restore merges entries and preserves conflicts. Keyboard, Streaming and Day Hub also have app-specific export/restore controls. A downloaded backup is a separate snapshot; entries written afterward require another export. Export before uninstalling Companion, switching between unpacked and store installations, clearing Companion data, or moving computers. The everyday user does not choose files or download backups while writing.

## Signing in and choosing a profile

Choose **Unlock browser** (before **Return to Hub**) to use the streaming website with a mouse and keyboard. The bar shows a reminder and keeps **Lock controls** available. This choice stays with that playback tab across sign-in page reloads. Choose **Lock controls** to restore switch scanning and focus protection. Alt+Shift+B toggles the same mode when the main page has keyboard focus. Netflix profile tiles can also appear as scannable bar choices; the Companion never selects a profile on its own.

The player dock distributes controls across its button lane and keeps playback and scan status inline at the far right. Narrow windows scroll the button lane while status remains visible. The video frame reserves the measured dock height.

Scan pause uses only a dotted outline on the selected Companion button; the shared outline-only policy adds no Paused text marker or badge. Parked status and normal playback feedback remain inline.
